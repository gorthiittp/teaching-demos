What the two curves are

Sweeping the threshold from 1 down to 0 produces a sequence of confusion matrices. Each curve plots a different pair of rates from that sequence, so a point on a curve is a threshold.

The ROC curve puts the false positive rate on x and recall on y. It always runs from (0,0) — threshold above every score, nothing flagged — to (1,1), where everything is flagged. Both denominators are fixed by the data rather than the threshold, which is why the curve doesn't shift when the class balance changes.

The precision–recall curve puts recall on x and precision on y. Its right-hand end lands at precision = π, the prevalence, because flagging everything gets you exactly the base rate. That endpoint moves whenever the class balance moves, and so does the whole curve.

One thing to keep straight: neither curve has the threshold on an axis. Dragging the slider slides the marker along a fixed curve; it doesn't reshape it.

What the areas mean

ROC-AUC has an exact probabilistic reading: it is the chance that a randomly picked positive scores higher than a randomly picked negative. It measures ranking, nothing else. 0.5 is the diagonal — coin-flip ordering.

PR-AUC is normally computed as average precision, a sum over thresholds rather than an area under an interpolated curve:

AP = Σ (Rₙ − Rₙ₋₁) · Pₙ

Straight-line interpolation between points in PR space describes classifiers that cannot exist, so it inflates the number. Its no-skill floor is π, not 0.5 — which means an AP is meaningless unless you report the prevalence beside it.

Why they disagree

The difference is entirely in the denominators. FPR divides false positives by the number of negatives, so when negatives are abundant, hundreds of false alarms barely register. Precision divides by TP + FP, so those same false alarms swamp the true positives directly.

Set prevalence to 2% and leave the model quality alone. ROC-AUC barely flinches; PR-AUC collapses. Both numbers are correct — they answer different questions.

Use ROC when the classes are roughly balanced, when both error types matter comparably, or when you need to compare across datasets with different prevalence. Use PR when positives are rare and it's the positive class you care about — screening, retrieval, fraud, lesion detection. One consequence of prevalence-dependence: a PR-AUC from your test set is not comparable to a published one unless the positive rates match.

What AUC cannot see

Both areas depend only on the order of the scores. Any transform that preserves order — cubing them, squashing them toward 0.5, pushing them toward the extremes — leaves ROC-AUC and average precision bit-for-bit identical, because no pair of samples changes places.

The four transform buttons do exactly that. Nothing about ranking changes; everything about the meaning of the number 0.7 does.

Calibration is the property AUC discards: whether samples scored 0.7 are positive about 70% of the time. Two numbers in the threshold-free row track it:

  • Brier score — mean squared error between score and label, lower is better. It mixes calibration and discrimination into one number.
  • ECE, expected calibration error — bin the scores, compare each bin's mean score to the fraction of positives it actually contains, and average the gaps weighted by bin size. It isolates calibration alone.

Watch those two climb while the ranking metrics sit still. The usual way to see this in full is a reliability diagram, which plots the same bins against the diagonal — worth drawing in a notebook when you get to your own model.

This matters the moment a downstream decision uses the score as a probability. Cost-optimal thresholds, risk scores shown to a clinician, and any expected-value calculation all assume calibration and silently break without it — while the AUC in your results table stays reassuringly high.

Choosing the operating point

An area is a summary over all thresholds; deployment needs exactly one. The usual routes:

  • Fix the constraint the application actually imposes — best precision subject to recall ≥ 0.90, or best recall within an alert budget.
  • Maximise Youden's J (recall − FPR), which assumes the two errors cost the same.
  • Maximise F1, or Fβ with β > 1 to weight recall higher.
  • Minimise expected cost: with a calibrated score, the optimal cut is t* = cFP / (cFP + cFN). Note the precondition.

Whichever you pick, pick it on validation data. A threshold tuned on the test set leaks, and the precision you report will be optimistic.

Things to try

  • Drag model quality to 0. Every sample gets the same score — the base rate — because a model with no signal has nothing to update the prior with. The ROC curve collapses to the diagonal and the PR curve to a flat line at π.
  • With rare positives, drag the threshold until precision and recall are equal, then read the confusion matrix. Notice how narrow the usable band of thresholds has become.
  • Switch to "over-confident" and read the two threshold-free ranking metrics, then the two calibration metrics. Explain to someone why only one pair moved.
  • Draw a new sample a few times at 2% prevalence and watch how much PR-AUC jumps. With only 40 positives, that spread is why both metrics need confidence intervals.
