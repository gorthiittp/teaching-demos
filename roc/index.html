What the two curves are

Sweeping the threshold from 1 down to 0 produces a sequence of confusion matrices. Each curve plots a different pair of rates from that sequence, so a point on a curve is a threshold.

The ROC curve puts the false positive rate on x and recall on y. It always runs from (0,0) — threshold above every score, nothing flagged — to (1,1), where everything is flagged. Both denominators are fixed by the data rather than the threshold, which is why the curve doesn't shift when the class balance changes.

The precision–recall curve puts recall on x and precision on y. Its right-hand end lands at precision = π, the prevalence, because flagging everything gets you exactly the base rate. That endpoint moves whenever the class balance moves, and so does the whole curve.

What the areas mean

ROC-AUC has an exact probabilistic reading: it is the chance that a randomly picked positive scores higher than a randomly picked negative. It measures ranking, nothing else. 0.5 is the diagonal — coin-flip ordering. It's unchanged by any monotone rescaling of the scores, so it says nothing about whether a score of 0.7 means a 70% chance.

PR-AUC is normally computed as average precision, a sum over thresholds rather than an area under an interpolated curve:

AP = Σ (Rₙ − Rₙ₋₁) · Pₙ

Straight-line interpolation between points in PR space describes classifiers that cannot exist, so it inflates the number. Its no-skill floor is π, not 0.5 — which means an AP is meaningless unless you report the prevalence beside it.

Why they disagree

The difference is entirely in the denominators. FPR divides false positives by the number of negatives, so when negatives are abundant, hundreds of false alarms barely register. Precision divides by TP + FP, so those same false alarms swamp the true positives directly.

Set prevalence to 2% and leave the model quality alone. ROC-AUC barely flinches; PR-AUC collapses. Both numbers are correct — they answer different questions.

Use ROC when the classes are roughly balanced, when both error types matter comparably, or when you need to compare across datasets with different prevalence. Use PR when positives are rare and it's the positive class you care about — screening, retrieval, fraud, lesion detection. One consequence of prevalence-dependence: a PR-AUC from your test set is not comparable to a published one unless the positive rates match.

Choosing the operating point

An area is a summary over all thresholds; deployment needs exactly one. The usual routes:

  • Fix the constraint the application actually imposes — best precision subject to recall ≥ 0.90, or best recall within an alert budget.
  • Maximise Youden's J (recall − FPR), which assumes the two errors cost the same.
  • Maximise F1, or Fβ with β > 1 to weight recall higher.
  • Minimise expected cost: with a calibrated score, the optimal cut is t* = cFP / (cFP + cFN).

Whichever you pick, pick it on validation data. A threshold tuned on the test set leaks, and the precision you report will be optimistic.

Things to try

  • Push model quality to 0. The ROC curve settles on the diagonal, but the PR curve settles on a flat line at π — find the prevalence slider value that makes a useless model look like it has precision 0.5.
  • With rare positives, find the threshold where precision and recall cross. Notice how narrow the usable range of thresholds has become.
  • Draw a new sample a few times at 2% prevalence and watch how much PR-AUC moves. That spread is why both metrics need confidence intervals when positives are scarce.
  • Compare two settings with the same ROC-AUC but different prevalence. The ranking quality is identical; the useful precision is not.
